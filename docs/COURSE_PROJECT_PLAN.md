## 1. 项目最终定位

项目名称暂定为：

**RumorBuster——基于 RAG 与 Agent 的可追溯谣言核验及传播时间线系统**

项目面向公开传播、具有事实含义且原则上可通过外部证据验证的网络主张。系统不承诺预测未来、调查私人事实或对主观观点判定真假。

最终业务流程：

```text
输入文字、网页 URL 或浏览器划词
→ 提取并标准化核心主张
→ 判断主张类型与可核验性
→ 检索已核验谣言知识库
→ 未命中时抓取原网页并检索独立证据
→ 生成支持、反驳和中立证据卡片
→ 重建基于公开证据的传播演化时间线
→ 执行引用真实性与证据强度校验
→ 输出并导出结构化核验报告
```

时间线只能称为“基于公开可检索证据重建的传播时间线”。系统显示的是本轮检索到的最早公开记录，不宣称发现了绝对传播源头。

## 4. 核心功能设计

### 4.1 主张类型与可核验性分流

建议的主张类型：

```text
public_fact          公开事实性主张
future_prediction    未来预测
random_future_event  随机未来事件
private_fact         私人事实
opinion              主观观点
satire               玩笑、讽刺或夸张
unclear              缺少明确主张
```

建议的可核验状态：

```text
checkable_now          当前可公开核验
checkable_later        未来才能验证
not_publicly_checkable 缺少合法公开证据或涉及隐私
not_a_factual_claim    不属于事实命题
```

最终结论标签：

```text
真实
虚假
误导
存疑
证据不足
暂不可核验
不可公开核验
非事实性表达
```

### 4.2 结构化核验结果

后端结果至少包含：

```text
核心主张
主张类型
可核验状态
判定结论
证据强度
支持证据
反驳证据
中立背景
核验局限
建议核验路径
来源列表
```

每条证据记录：

```text
来源标题
发布主体
发布时间
来源 URL
证据原句或摘要
支持/反驳/中立
来源类型
日期精度
可追溯状态
```

### 4.3 谣言传播时间线

时间线事件类型：

```text
earliest_found  本轮最早检索记录
spread          扩散节点
mutation        内容变体
amplification   夸大传播
verification    核验节点
correction      澄清或辟谣
resurgence      再次传播
```

每个时间线卡片至少包含：

- 时间和日期精度；
- 当时传播的主张版本；
- 与上一版本的主要变化；
- 事件类型；
- 发布主体和来源标题；
- 证据摘要；
- 来源 URL；
- 支持/反驳/中立；
- 证据可信状态。

时间线 MVP 的验收标准：

- 每个演示案例生成 3 至 8 个有效节点；
- 节点按时间排序；
- 没有可靠日期时显示“日期不确定”；
- 重复转载不重复显示为独立事实；
- 每个确定性节点都有可点击来源；
- 页面明确提示“最早检索记录不等于绝对源头”。

### 4.4 已核验谣言知识库与 Agent 分工

```text
输入主张
→ 检索知识库
   ├─ 高度匹配：直接返回已有权威核验记录
   ├─ 部分匹配：Agent 比较时间、地点、人物和说法变化
   └─ 未命中：Agent 执行网页抓取、搜索和证据分析
```

如果最终没有实现向量检索，材料中应称为“已核验谣言知识库检索”，不能包装成 RAG。

## 9. 答辩重点与标准回答方向

### 为什么需要 Agent？

任务包含主张提取、网页读取、独立搜索、证据聚合、时间线重建和报告生成，是多步骤、有状态、有工具调用的流程。已知谣言精确命中时不调用 Agent，只有变体或新主张才进入复杂核验。

### 这是不是大模型套壳？

项目包含网页安全抓取、SSRF 防护、知识库检索、工具调用限制、引用真实性中间件、证据不足强制降级、会话持久化、自动测试和可视化时间线，不依赖单次模型回答完成全部工作。

### 如何证明效果？

通过直接问模型、模型加搜索和完整 RumorBuster 三组对比，报告准确率、F1、引用可追溯率、虚构链接率、正确拒答率、延迟和失败案例。

### 时间线是不是完整传播源头？

不是。时间线只基于公开可检索证据，展示本轮检索到的最早公开记录和关键传播节点，私人群聊、已删除内容和未被索引页面可能无法覆盖。

### 如何处理未来预测和隐私事实？

先执行可核验性分类。未来预测标记为“暂不可核验”，只能核查其依据；随机结果不进行预测；私人事实标记为“不可公开核验”，不进行调查或推测。

## 10. 风险与应对

| 风险 | 应对策略 |
|---|---|
| 搜索结果不稳定 | 固定演示案例、保存备用结果、限制查询次数 |
| 网页无法抓取 | 明确失败状态，保留文本输入路径，不猜测正文 |
| 模型虚构链接 | 运行时只允许引用当前工具返回的 URL |
| 时间线虚构日期 | 保存日期来源和精度，不确定时显式标记 |
| 功能范围失控 | 8 月 11 日冻结功能，按 P2、P1 顺序删减 |
| 答辩被问准确率 | 提前完成评测集、对比实验和失败分析 |
| 现场网络或 API 故障 | 本地容器预启动，准备预录演示和静态结果 |
| 密钥泄露 | 提交前运行密钥扫描，只提交示例配置 |
| 成员贡献争议 | 日志、Issue、Commit 和材料产物共同留痕 |

## 13. 执行原则

1. 可解释、可追溯和可量化优先于功能数量；
2. 每个新功能必须有测试、文档和可演示案例；
3. 不把模型记忆包装成检索证据；
4. 不把关键词检索包装成向量 RAG；
5. 不把最早检索记录包装成绝对传播源头；
6. 不为了提高实验数据而删除失败样本；
7. 8 月 11 日后以稳定、材料和答辩为主，不继续堆高风险功能。
