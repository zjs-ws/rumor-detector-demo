# 真实判定能力修复与验收

## 为什么需要这轮修复

组件测试通过只能证明 Schema、分支和规则函数按预期工作，不能证明开放互联网中的主张一定能被正确判定。2026-08-14 的 NASA“丢失一天”、CIA/MKULTRA 和塔斯基吉研究实测暴露了三类问题：历史事件被领域词误判为当前状态、权威研究没有锁定对应机构，以及模型摘要没有可反查的正文引文。

本轮不降低“一条直接且职权匹配的 A，或两条独立直接 B”门槛，而是改善门槛之前的检索、抓取和验证。

## 修复后的调用链

```text
主张与子主张
→ 确定性时态修正
→ 实体别名与受控机构 research_plan
→ 普通发现检索（发现正式名称、支持与反驳材料）
  ║ 与权威定向检索并行（锁定 site: 官方域名）
→ 正文抓取
→ excerpt 在正文中反查 + SHA-256 文档哈希
→ URL、职权、时效、独立性校验
→ 一条 A / 两条独立 B 的确定性裁决
→ report-v3 与前端审计
```

搜索不到、页面没有提及主张、搜索摘要以及 RAG 命中都不能构成反驳证据。历史事件不使用365天淘汰；无时态标记的普遍性事实（如抽烟有害健康）由代码确定为 general，同样不适用 365 天淘汰，职权匹配的权威旧证据可直接裁决；当前政策、指南和现状主张仍需要近期材料或可验证的当前有效性确认。

## 30条真实联网验收

清单位于 `evaluation/real_e2e_cases.json`，由10条离奇但真实的历史主张、10条公开虚假流言、5条当前状态主张和5条确实不足或含混的主张组成。它不是训练数据，也不是 RAG 语料。

服务启动后执行：

```bash
docker compose -f compose.prod.yaml run --rm -T \
  -v "$PWD/evaluation:/app/evaluation" \
  langgraph uv run python scripts/evaluate_real_factchecks.py \
  --base-url http://langgraph:2024 \
  --strict \
  --output-dir evaluation/real_e2e_runs/final
```

验收同时要求：

- 可由公开权威材料解决的25条中，明确判定率不低于80%；
- 已明确判定案例的准确率不低于90%；
- 报告证据 URL 均来自本轮工具观察；
- 参与裁决的直接网页证据均有可反查 excerpt、抓取状态和文档哈希；
- 工作流裁决与 report-v3 结论一致。

生成的 `summary.json` 明确标记 `run_kind=live_end_to_end_not_mock`。没有真实运行产物时，不得在报告、PPT 或答辩中填写上述指标。

## 四条阻断回归

- 塔斯基吉：应路由 CDC/HHS/Archives，历史档案不因页面年代旧或缺少发布日期被排除；取得直接职权匹配材料后判“非谣言”。
- MKULTRA：应路由 CIA/Senate/Archives；取得解密原始资料后判“非谣言”。
- NASA“丢失一天”：无关 NASA 页面和“NASA没有提到”必须排除；只有直接反驳材料达到规则门槛才判“谣言”，否则保持“证据不足”。
- 抽烟有害健康：应路由 WHO/CDC/NHC 健康职权；主张无时态标记，时态应为 general 而非 current_status；CDC 吸烟与心血管页面（2024/2025）经抓取与 excerpt 反查后可作为职权匹配的 A 级支持证据，裁决“非谣言”，不得因发布时间超过 365 天被排除。

在四条回归稳定通过两次、30条验收达到门槛前，项目定位使用“可追溯证据辅助核验系统”。
