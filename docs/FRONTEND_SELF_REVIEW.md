# RumorBuster 前端三轮自审记录

审查日期：2026-08-14

生产入口：`http://localhost:8080`

分支：`feature/import-mcp-frontend`

## 第一轮：事实表达准确性

| 检查项                          | 结果 | 证据                                                              |
| ------------------------------- | ---- | ----------------------------------------------------------------- |
| 规则 verdict 是唯一最终结论     | 通过 | 结论首屏固定说明 RAG、LoRA、通用大模型不能覆盖规则                |
| 并行分支没有画成串行            | 通过 | 七阶段中只有“并行取证”包含四张横向分支卡                          |
| 来源等级使用代码校正值          | 通过 | 证据卡同时展示声明等级、校正等级和原因                            |
| 未观察或非法 URL 不变成链接     | 通过 | ViewModel 只允许 HTTP(S)，纯函数测试覆盖 `javascript:` 和 `file:` |
| RAG、LoRA、文本风险未冒充证据   | 通过 | 三者位于辅助层并持续显示边界提示                                  |
| 时间线未冒充绝对源头            | 通过 | 少于三个节点不显示；最早节点称“本轮最早检索记录”                  |
| 分类器不可用未写成跳过          | 通过 | `unavailable` 显示黄色不可用状态和降级说明                        |
| v1/v2/v3 缺失或未知字段安全降级 | 通过 | 统一 ViewModel；未知值显示“未知状态”                              |

本轮修复：

1. 删除首页图片/OCR 能力暗示；
2. 修正 V3 步骤条为“并行取证—汇合校验—规则裁决”；
3. 修正 `mixed` 和非法 LoRA 标签可能被误读为非谣言的边界；
4. 正式导出删除 reasoning、工具调用和敏感字段。

## 第二轮：信息层级与视觉

五秒测试结果：

- 主张：报告首屏左上可以直接找到；
- 结论：右侧高对比 verdict 徽标，无需滚动；
- 依据：首屏显示证据强度、采用/排除数量，下一区域默认进入裁决证据；
- 来源：证据标题是安全 HTTP(S) 链接；
- 信号边界：LoRA、RAG、文本风险与规则证据分别呈现；
- 技术信息：trace、错误码和 schema 默认折叠，不抢普通用户注意力。

亮暗主题均使用 RumorBuster 语义色。首页允许细网格与局部光晕，报告使用稳定卡片；持续动画只用于运行阶段，并在 `prefers-reduced-motion` 下关闭。

## 第三轮：对抗式交互与生产检查

已实际检查：

- 390×844、768×1024、1280×720、1440×900；
- 亮色与暗色；
- 首页、医学案例、URL 案例、非事实边界案例；
- 零条采用证据、存在排除证据、LoRA 不可用、时间线不足；
- 非法 URL、非法分类枚举、少于三个时间线节点；
- Nginx 单入口、四容器健康和聚合 `/healthz`；
- 浏览器控制台。

发现并修复：

1. 历史案例日期曾因服务端与浏览器默认时区不同触发 React hydration 错误；固定 `Asia/Shanghai` 后，新浏览器会话控制台为 0 错误。
2. 初次 macOS Chrome 无头截图把最小布局宽度裁成 390px，容易误判为页面溢出；改用 CDP `set viewport` 后确认真实 390px 下 `innerWidth=390`、`scrollWidth=390`，报告卡宽度为 358px。
3. 首页标题和输入容器补充 `min-width: 0`、移动端最大宽度与可换行约束，避免长中文标题撑开 flex 容器。

尚未自动构造 30 条证据的超长 Fixture 页面；证据列表本身为正常文档流，长 URL 已使用换行类，后续只在真实报告出现该极端数据时复测，不在存档案例中伪造数据。
